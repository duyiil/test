## 1. 项目是什么

智测（ZhiTest）是一个软件测试与质量保障平台。核心思路：**维护项目与接口契约 → 生成测试用例 → 人工审核 → 独立 Worker 对 HTTP 接口执行 → 四种断言给出数据报告**。

- 配置了 LLM 密钥时，用例生成和失败研判走 OpenAI 兼容接口（默认 DeepSeek）；
- 没有密钥时，生成走 Mock（只依据契约结构生成），研判状态保持 `unavailable`，不会把 Mock 说成模型分析；
- 执行目标是 HTTP 接口（REST），**不执行用户提交的源码**（已明确列为未做）。

仓库原始资料有缺口：《需求文档 V1.3》《架构设计 V0.1》《Demo 接口契约 V0.1》《团队开发规范 V1.0》《智测原型.html》都不在仓库里，Sprint 与测试用例以仓库内两份 xlsx 为准。因此本项目是一份「根据已有材料重建 + 补全」的实现。

## 3. 架构与进程模型

```
┌────────────┐   HTTP(5173, /api 代理)   ┌──────────────┐
│  浏览器前端  │ ────────────────────────▶ │  API (8000)  │  FastAPI + SQLAlchemy
│ React+Vite │                          └──────┬───────┘
└────────────┘                                 │ 读写
                                    ┌──────────▼──────────┐
                                    │   PostgreSQL (5432)  │  23 张表：任务状态即队列
                                    └──────────▲──────────┘
                                                │ 轮询认领（生成任务/执行任务）
                                    ┌───────────┴──────────┐
                                    │  Worker (python -m   │  app.worker
                                    │   app.worker)         │  独立进程，只发 HTTP 测试
                                    └───────────┬──────────┘
                                                │ 对被测目标发 HTTP
                                    ┌───────────▼──────────┐
                                    │ 被测服务 SUT (9000)   │  demo/sut/main.py（演示用）
                                    └──────────────────────┘
```

- **API**：`app/main.py`，启动时（`ZHITEST_AUTO_BOOTSTRAP=true`）自动创建管理员账号；`/api/v1` 前缀；统一响应结构 `{code, message, details, requestId, data}`；全局异常处理；会话 Cookie `zhitest_session`（HttpOnly、SameSite=Lax、默认 7200 秒滑动过期）。
- **Worker**：`app/worker.py` 的 `tick()` 循环 —— 先恢复过期租约（`recover_stale_runs`，不重放已完成步骤），再认领生成任务，没有生成任务才认领执行任务。执行走 `app/execution/runner.py`。
- **SSRF 防护**：执行目标默认只允许 `127.0.0.1`、`localhost`、`::1`（`ZHITEST_TARGET_ALLOWLIST` 控制），私网/链路本地/元数据地址一律拒绝；重定向后的地址也重新校验。
- **幂等**：创建执行任务可带 `Idempotency-Key` 请求头，重复提交不会产生两次执行。

## 5. 核心主链路（Phase 2 主路径）

1. **创建项目**：名称 + 描述 + Base URL（被测服务地址）+ 环境标签。
2. **载入契约**：页面点「载入演示契约」（`demo_contract.py`），或导入 OpenAPI 3.x JSON/YAML（先预览、确认后写入）。
3. **生成用例**：创建生成任务 → Worker 认领。无密钥走 `MockGenerationProvider`（按契约结构生成）；有密钥走 `LLMGenerationProvider`（OpenAI 兼容格式，记录 provider 与 model）。
4. **审核**：用例为 draft → 提交 → 通过 / 驳回（驳回必须写原因）；支持批量。
5. **执行**：创建执行任务（写操作需勾选确认 `confirmWrites`）→ Worker 认领 → 逐条发 HTTP → 每用例一次租约心跳，租约过期可被恢复且不重放已完成步骤 → 可取消。
6. **报告**：数据报告与 AI 研判分离。四种断言（statusCode / jsonType / bodyContains / jsonPath 类），支持 HTML / JSON 导出。未配置密钥时 AI 状态为 `unavailable`。

**四种断言**（`app/execution/assertions.py`）：状态码、JSON 字段类型、响应体包含、JSONPath 取值比对；另有 `{{var}}` 变量提取与依赖顺序、回归用例集。

## 9. 本次发现并修复的问题

**问题**：Worker 执行测试时，所有请求得到 `502`（空 body），但 curl 直连被测服务正常。

**根因**：本机 Windows 系统代理开启（`HKCU\...\Internet Settings` → `ProxyServer=127.0.0.1:7897`，Clash）。httpx 默认 `trust_env=True` 会读取系统代理设置，把测试流量转发给 Clash，Clash 拒绝代理回环地址 `127.0.0.1` 并返回裸 502。curl 不读 Windows 注册表代理所以正常。

**修复**：`zhitest/backend/app/execution/runner.py` 的 `_http_transport` 中，httpx.Client 增加 `trust_env=False`（并加注释说明）。测试流量必须直连被测目标，不能走宿主机代理；而 `modules/ai/llm_provider.py` 里的 DeepSeek 客户端**保持默认**，因为国内访问 api.deepseek.com 恰恰需要代理。修复后 62 条 pytest 全部通过，E2E 重跑通过率从 0% 变为符合预期的 29%。

> 注意：这是对仓库代码的一处修改（未提交）。如果将来部署到 Linux 服务器且服务器没有系统代理，此改动无副作用；有代理的服务器上它同样是正确行为。

### 13.1 TriageProvider mock 研判（7 类内置 bug 规则）

- 实现：`zhitest/backend/app/modules/ai/mock_triage.py` 的 `MockTriageProvider`
- 行为：没有配置真实模型密钥（`ZHITEST_LLM_API_KEY` 为空）时，报告不再显示 unavailable，而是按 **7 类内置 bug 规则**对断言失败做模式匹配，输出分组根因与定位建议；报告 `aiStatus` 变为 `mock`，结论开头标注「规则研判（Mock，未调用真实模型）」，结尾注明仅供参考，不冒充模型分析
- 7 条规则与 demo/sut 的 7 个预埋缺陷一一对应：

| # | 规则 key | 缺陷 | 匹配信号 |
| --- | --- | --- | --- |

| 3 | price_type_not_validated | price 字符串仍 201 | 期望 400 实际 201 + 用例名含「字符串/类型」 |
| 4 | price_boundary | price=0 仍 201 | 期望 400 实际 201 + 用例名含「为 0/边界」或响应片段含 `"price": 0` |
| 5 | name_max_length | name 超 40 字符仍 201 | 期望 400 实际 201 + 用例名含「长度」 |
| 6 | seed_data_type | 预置商品 price 为字符串 | jsonType 期望 number 实际 string |
| 7 | duplicate_name | 重名商品重复创建 | 期望 400 实际 201 + 用例名含「重复/重名」 |

## 14. GitHub 项目接入（网址检测 + 生成用例）

- 后端：`zhitest/backend/app/modules/github/service.py` + `app/api/v1/github.py`
- 前端：项目详情页「GitHub 项目接入」卡片（`ProjectDetailPage.tsx`）

### 14.1 能力

1. **检测项目**：`POST /api/v1/projects/{id}/github/detect`，入参 `{url}`。只接受 github.com 主机（其余主机一律拒绝，防 SSRF）；返回仓库信息（名称/语言/默认分支/文件数）、框架指纹（pom.xml→Java/Spring Boot、pyproject→Python、package.json→Node.js 等）与候选接口定义文件（openapi/swagger 的 json/yaml，常见目录 + 任意深度兜底，逐个尝试解析并返回接口数或错误原因）
2. **导入接口**：`POST /api/v1/projects/{id}/github/import`，入参 `{url, specPath, autoGenerate}`。通过 GitHub contents API 读取文件（base64，上限 2MB）并复用 OpenAPI 确认链路导入；`autoGenerate=true` 时导入后立即入队用例生成任务
3. **生成用例**：生成走既有链路（无密钥 Mock / 有密钥 DeepSeek），前端「导入并生成用例」一键完成

### 14.2 配置

- `ZHITEST_GITHUB_TOKEN`（可选）：GitHub API 令牌，匿名限流 60 次/小时（检测一次约消耗 3~4 次请求）
- `ZHITEST_GITHUB_PROXY`（可选）：本模块显式代理地址。模块默认**不走宿主系统代理**（部分机器上系统代理无法路由 api.github.com），直连被墙时用它指定代理

### 14.3 联调实录

对 `https://github.com/swagger-api/swagger-petstore` 执行检测：识别为 Java / Spring Boot（50 个文件），在 `src/main/resources/openapi.yaml` 找到接口定义，解析出 **19 个接口**；执行「导入并生成用例」→ 保存 19 个接口、3 个旧演示接口自动禁用、Mock 生成任务完成 → **42 条草稿用例，覆盖 22 个接口**。

### 14.4 限制

- 只支持公开仓库（或配置了令牌后可见的仓库）与 OpenAPI 3.x 文档；OpenAPI 2.0 与无接口文档的项目会给出明确提示（无文档项目可手工粘贴 OpenAPI 或用「手工录入」）
- 生成出的用例的 Base URL 仍是项目配置的目标地址，需在项目设置中指向被测服务的真实地址后执行
