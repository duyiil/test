# 可替换默认值

以下决定只在对应原始文档缺失时使用。原始文档补齐后应以原文档为准，并回改这里列出的接口和数据模型。

1. 没有《架构设计 V0.1》。采用任务说明中的模块化单体：浏览器、API、PostgreSQL。Phase 1 没有异步任务，因此不引入 Celery 和 Redis。等执行任务出现时再评估队列，并与当时的接口契约和任务状态一起看。
2. 没有《Demo 接口契约 V0.1》，也没有 6 张既有基础表。响应在任务说明给出的 `code`、`message`、`details`、`requestId` 之外增加 `data` 承载业务数据。错误响应不带 `data`。详见 `docs/api-contract-phase1.md`。这份文件不是 V0.1。
3. 没有《需求文档 V1.3》。功能范围以任务说明的 Phase 1 为准，编号和用例步骤引用仓库里的 Sprint 表和测试用例表。两份计划冲突时只记录，不改表格。
4. 没有原型 HTML。界面按任务说明的深蓝后台布局实现，不声称还原了评审稿。
5. 没有团队开发规范。提交使用可读说明。分支名遵循本次任务要求的 `cursor/<name>-3a85`。
6. 会话使用 HttpOnly Cookie，不把令牌放进 localStorage。空闲超时 7200 秒来自测试用例 TC-CONFIG-008，不是来自缺失的需求文档。本次没有做两小时墙钟等待，只验证了过期判断和配置值。
7. 项目名称在同一所有者下按区分大小写的完整字符串唯一。
8. 创建项目时不访问 Base URL。允许保存本机地址，供以后的演示服务使用。拒绝在 URL 里写入用户名或密码，避免把口令明文放进项目表。SSRF、DNS 和跳转校验还没有做，因为服务器尚未对外发起测试请求。
9. 其他用户的项目返回 404，列表也不可见。已知的管理员接口对普通成员返回 403。
10. 用例、执行、报告的表还没有建。对应计数是 0，任务列表为空，通过率是 null，文案为“无可判定结果”。
11. 初始管理员由环境变量创建。用户已存在时不重置口令。示例口令 `ChangeMe-Admin-2026` 只用于本地开发。
12. 密码使用 bcrypt，长度限制 8 到 72 字节。不开放注册。
13. 默认不信任 `X-Real-IP`。只有 `ZHITEST_TRUST_PROXY=true` 时才读取，Compose 里会打开。
14. Python 使用环境中的 3.12.3。任务说明允许与现有环境兼容的版本，仓库本身没有锁定 3.11。
