# 作者自建的演示被测服务

`demo/sut/main.py` 原先不在仓库中。这里的服务和下面的行为都是 Phase 2 开发时新写的，用来让「生成 → 审核 → 执行 → 数据报告」能打到一个本机 HTTP 服务。它不是团队缺失的那份 Demo，也不能把它说成团队已经预埋好的 7 个缺陷。

启动：

```bash
cd demo/sut
python3 main.py
```

默认监听 `http://127.0.0.1:8001`（柴诗雨联调端口）。Phase 2 的执行器只允许访问本机地址。

契约在 `zhitest/backend/app/modules/ai/demo_contract.py`，由页面上的「载入演示契约」写入项目。生成器只读这份契约，不导入本目录。

本服务故意和那份契约不一致的地方：

1. `GET /api/products/{id}` 在商品不存在时仍返回 200，`name` 和 `price` 为 null。契约声明了 404。
2. `POST /api/products` 缺少 `name` 时仍返回 201。
3. `price` 传字符串时仍返回 201，并原样保存。
4. `price` 为 0 时仍接受。契约最小值是 0.01。
5. `name` 长于 40 个字符时仍接受。
6. 预置商品 `p-1` 的 `price` 是字符串 `"12.5"`。
7. 相同 `name` 可以重复创建，每次都返回新的 201。

这些差异要靠执行结果里的断言失败来观察。生成器不会把上述条目写成「已经发现的缺陷」。输入被接受也不等于确认存在注入漏洞。
